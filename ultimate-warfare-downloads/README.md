# Ultimate Warfare — комплект первого прототипа

Актуальный комплект — **0.1.5**. Эта ветка предназначена для передачи файлов мода.

- `UltimateWarfare-0.1.5-source.zip` — исходный комплект для оригинальной Zero Hour 1.04.
- `uwlongma-preview.png` — оригинальный рендер модели «Лунма» в Blender.

Откройте файл на GitHub и нажмите **Download raw file**. Старые ZIP сохранены для воспроизводимости; для следующего теста нужен 0.1.5.

Распакуйте ZIP отдельно и откройте вложенную папку `UltimateWarfare-0.1.5`, где находятся `README.md`, `scripts`, `tools` и `content`. Откройте там PowerShell и выполните сборку:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Build-Mod.ps1 -GameDir "C:\Program Files (x86)\R.G. Mechanics\Command and Conquer - Generals\Command and Conquer Generals Zero Hour"
```

Нужен Python 3.10+. 90 автоматических тестов проходят на синтетических данных. На Windows пользователя 18 BIG уже индексируются; обнаруженный отказ парсера на `AttackAreaDecal` исправлен в 0.1.5 вместе с поддержкой связанных RadiusDecal-блоков. Сборка на реальных данных ещё требует повторного запуска. Работа танка в игре пока не подтверждена.

При ошибке передайте строку `ERROR:`. Диагностика через `Prepare-Test.ps1` также доступна и теперь сообщает структурные сведения в `ini_error`. Файлы установки игры не изменяются; ZIP не содержит её исполняемые файлы, архивы или личный BIG мода.

## Дополнительная диагностика строки INI для 0.1.5

Если сборка сообщает только номер строки, сохраните `explain_ini.py` этой папки в `tools` локального комплекта. Запустите из корня проекта:

```powershell
py -3 .\tools\explain_ini.py --game-dir "C:\Program Files (x86)\R.G. Mechanics\Command and Conquer - Generals\Command and Conquer Generals Zero Hour" --report .\dist\ini-error-details.json
```

Этот отдельный диагностический отчёт включает **одну проблемную строку исходного INI** (до 512 байт), её представление в hex и структурные сведения. Обычный `doctor` по-прежнему выдаёт только метаданные. Файлы игры не изменяются, игровой процесс не запускается. Существующий отчёт не перезаписывается; для повтора задайте новое имя через `--report`. Передайте только этот JSON для выяснения точного синтаксиса ошибки.
